# DiscShift 1.0 readiness

The intended 1.0 scope is an Apple Silicon, macOS 14+ TV-episode workflow with hardware encoding. Keep movies, combined-title splitting, Intel support, persistent queues, and automatic retries for later unless the supported scope changes. An interrupted queue can require starting again; that limitation must be clear before export.

The source, automated tests, release checks, and observations behind the current status are recorded in [VALIDATION.md](../VALIDATION.md). A passing build or successful encoding message alone does not establish correct playback.

## Required before 1.0

- [ ] **Complete the real disc-to-library path.** Export a full physical DVD queue, confirm every title maps to the intended episode, let Jellyfin import it, and play the beginning, middle, and end of every episode. Verify long-running audio sync, aspect ratio, interlaced motion, seeking, chapters, and available audio/subtitle choices. Record disc, Mac, macOS, reader version, export settings, output sizes, and actual client results. Short excerpts and a progress screen are insufficient.
- [ ] **Validate finished files before reporting success.** The current export path requires a successful reader exit, confirmed hardware encoder, and nonempty output. Add an independent check of readable media tracks and expected duration before moving the file into the season folder; tolerate normal DVD timestamp differences, but reject a materially truncated or unreadable output. Test both valid files and a reader that exits successfully with a bad output.
- [ ] **Finish fresh setup testing.** Use a separate Mac or fresh user account with no app/settings/reader. Download through Safari, open with normal macOS security prompts, verify Applications installation and Downloads cleanup, install the reader and included DVD support, then scan and export. Also exercise the no-Homebrew path, denied folder access, canceled/failed setup, retry, and a second launch without repeating setup. The no-Homebrew instructions need to be understandable to a nontechnical tester; simplify them if they are a stumbling block.
- [ ] **Exercise failures on disposable fixtures.** Cancel partway through a multi-episode queue; quit during export; remove a test disc/source; use an unwritable or full test destination; disconnect a test network destination if that is a supported use case. Completed files must remain playable, final files must never be overwritten, incomplete outputs must stay out of the season folder, and the app must explain how to recover. Cover force quit/relaunch honestly without promising resume.
- [ ] **Verify the supported Macs and interface.** Run on macOS 14 and the current macOS release on Apple Silicon, including a normal non-admin account. Check keyboard-only navigation, VoiceOver labels, light/dark appearance, the smallest supported window, long show names, and error messages. Intel is not a 1.0 requirement while the download is explicitly Apple Silicon only.
- [ ] **Finish real installer/update checks.** Test a Safari-quarantined launch, existing same/newer/older copies, a running installed copy, and fallback to the user's Applications folder. Update the previous public version through the signed feed with preferences preserved. Confirm an update cannot interrupt a scan, dependency installation, or export. The signing, notarization, and push-to-release pipeline already have successful public releases; rerun them for the final candidate.
- [ ] **Prepare the public release.** Publish clear requirements, setup help, limitations, privacy behavior, dependency/metadata/framework credits, screenshots, and a GitHub issue path. Check notices for shipped components and external tools. Have at least two people outside development complete the main workflow without coaching; fix any blockers they encounter before changing `prerelease` to false.

## Current evidence

- Public releases are Developer ID signed, Apple notarized, stapled, and Gatekeeper-accepted. The signed archive/feed pipeline is live.
- An actual older notarized build updated through Sparkle to 0.9.0 and preserved the checked preferences. The installed 0.9.1 app checked the public feed successfully.
- Hardware encoding, all four containers, multiple audio tracks, text subtitles, chapters, file protection, and cancellation have automated checks and/or short integration observations. Full-length playback and a complete multi-title disc in Jellyfin still need explicit results.
- A physical 0.9.1 copy installed into Applications and reopened successfully. A real Safari download revealed that translocation leaves the original Downloads app behind; 0.9.2 adds verified Downloads-copy cleanup for that case. The cleanup helper passed against that real translocated source, and the public 0.9.2 installer replaced an older copy, reopened, and removed its Downloads copy. Complete browser-to-first-launch testing and user-Applications fallback remain open; see VALIDATION.md for the exact distinction.
- Existing setup installs and simulated setup failures have been exercised. A no-Homebrew clean-Mac installation and minimum-OS validation remain open.

## Release decision

Ship a 1.0 candidate after the required checks have recorded results and no data-loss, wrong-episode, broken-playback, failed-installation, or failed-update issue remains. Optional features do not need to hold that release. Keep the public build a preview until the evidence supports changing that label.
